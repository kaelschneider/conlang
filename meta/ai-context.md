# AI Context and Maintenance Rules

## Read order

1. `canon/overview.md`
2. Relevant canonical domain file(s)
3. Relevant historical/diachronic file(s)
4. `development/open-questions.md`
5. `development/decisions.md`

## Authority

- `canon/` is the authoritative description of the current language.
- Domain-specific files outside `canon/` may contain detailed canonical data; when they conflict with an overview, resolve the conflict explicitly rather than silently choosing one.
- `development/` contains hypotheses, unresolved questions, and decision history. It is not itself grammar.
- Historical reconstructions must be distinguished from synchronic forms.

## Editing rules

- Do not silently resolve contradictions.
- Do not promote a hypothesis to established status merely because it appears in an earlier conversation.
- Preserve explicit user decisions even when a different analysis seems typologically preferable.
- When a new decision changes an existing rule, update all affected canonical files in the same change.
- Examples must conform to the current morphology; do not preserve an obsolete example merely because it appeared previously.
- Keep phonological repair distinct from morphological substitution.
- Treat surface CVC forms and historical/morphological structure as separate analytical levels.

## Current development focus

- Stabilize the ordered sound laws.
- Reconcile case/applicative analyses.
- Stabilize the verbal template and auxiliary semantics.
- Expand syntax only after core morphology is internally consistent.
- Build machine-readable lexicon data once the root inventory is sufficiently stable.
